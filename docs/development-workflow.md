# Development workflow (contributors)

This page is for people working on the codebase. Product and install docs are in the root `README.md`.

The project is built by a small team of agents (CEO, backend, frontend, tester) working under strict rules: tests first, nothing merged without the Admin's approval, and a safety guard against destructive actions. The rules live in `CLAUDE.md` and `.claude/`; only the Admin changes them. Start with `claude --agent ceo`.

## How a feature flows

| Step | Who | Admin approves? |
|------|-----|:---:|
| Listen, restate, MCQ cross-questions, requirement tree | CEO | ✅ tree |
| 2–3 approaches with pros/cons → ADR | CEO | ✅ choice |
| Plan + tasks + why each agent + model per task | CEO | ✅ plan |
| Assign tasks (worktrees if parallel) | CEO | ✅ assignment |
| Failing tests: positive / negative / edge | tester | — |
| Code to pass tests, then refactor | backend-dev / frontend-dev | — |
| Verify + coverage report | tester | — |
| Review diff, run checks, report | CEO | ✅ merge |
| Merge `--no-ff` into main, rebuild docs | CEO | — |

Everything is browsable at `docs/html/index.html` (generated by `python scripts/build_docs.py`).

## Safety — what the guard blocks

- `rm -rf`, `git reset --hard`, `git clean`, force push, `branch -D`, `find -delete`, `DROP TABLE`
- Reading or writing outside the project, `~`, `/Users`, `.ssh`, `.aws`, Documents/Downloads…
- `.env`, keys, credentials (`.env.example` is allowed)
- Uploading data out (`curl -d/-F/POST`, `scp`, `nc`, `curl | sh`)
- Editing `CLAUDE.md`, `.claude/`, `.git/`
- Running migrations (`alembic upgrade` etc.): the Admin runs the migration
- Sub-agents writing outside their folder (enforced by the agent rules and the CEO's diff review)

Merges, pushes, dependency installs and file deletions always show a permission prompt.

> The guard is a strong safety net, not a guarantee. Keep `main` protected on GitHub (require PR + passing checks) and push regularly.

## Changing the rules

Only the Admin edits `CLAUDE.md` and `.claude/`. Agents may *propose* new skills or agents; the Admin approves and adds them.

## Quality checks (same as CI)

```bash
uv run pytest -q
uv run ruff check backend tests
uv run ruff format --check backend tests
uv run mypy --strict backend/vidgen
cd frontend && npm run typecheck && npm run lint && npm run format:check && npm test
```
