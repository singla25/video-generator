1. What we are building and why

VidGen Studio makes personalised campaign videos. You give it one template video and a sheet of names. It makes one video per row, where the spoken name (for example "Krishan") is replaced by the row's name, in the cloned voice, with the lips matching. Every video carries a small "AI" label, and the voter list is encrypted.

Two ways to run it:

  • Mac local (the main product). All the AI runs on your Mac's GPU. Nothing leaves the Mac. Slower: a 24 GB Mac

works but swaps heavily.

  • Cloud GPU (Modal, later). Faster, but the data goes to a cloud service.

The C5 privacy rule: in cloud mode only demo data (a neutral demo template and made-up names) is allowed. Real voter data never goes to the cloud. The installer and the app enforce this.

Kaggle GPU trial (2026-11-22, free, no cloud cost)

On one T4 (Python 3.13, torch 2.11.0+cu130): Chatterbox load 17.9 s, warm generation 4.24 s for 3.84 s of audio, peak 3.2 GB, float32. Whisper small: load 0.6 s, run 0.69 s, 743 MiB. Whisper medium: load 11.1 s, run 0.71 s, 1963 MiB, higher word confidence (about 0.91 vs 0.65 on the first word). Whether both found the name is not yet confirmed by the Admin. MuseTalk was not tested. Details and caveats: docs/kaggle/KAGGLE-T4-TRIAL.md.

  • Recommendation: Whisper medium on a GPU, small on the Mac.
  • Which cloud option still makes sense: GPU speed is not the blocker (voice about 1.1 times real time warm, speech-to-text under

one second on a T4-class card). So if a cloud worker is ever resumed, a single T4 or L4 class GPU, pay per use, is enough for speech and voice. The open question is lip sync (MuseTalk), which was not measured and has the licence decision (BL-7, G8). Modal stays parked. The next cloud-related step costs nothing: run MuseTalk on Kaggle by hand the same way, made-up data only. Kaggle stays a manual measuring tool, never a render worker.
