Plan — Better name detection in the template (BL-6)

Status: APPROVED by the Admin on 2026-11-22 (overnight run, DD-41). Decisions: 1 candidates only in the response (no migration); 2 plain sound rules (no new library); 3 closeness 0.8 as an adjustable setting; 4 download Whisper small and medium weights into the git-ignored weights folder, not large-v3. Starts after: PR #25 is merged (done) and migration 0003 is done (it is, on vidgen). Reason: this plan adds an optional hint argument to the speech-to-text port, and the Modal adapters in #25 implement that port too.

Goal

When you upload a template and type the name that is spoken in it (for example "Krishan"), the app finds that word in the audio far more often. Today it must match exactly, and it often misses. When it still cannot find it, it shows the closest 3 words so you can pick one instead of marking the time by hand.

Why it fails today (from the code)

  • TemplateService.analyse (services/templates.py) calls select_target_word (domain/slot_match.py).
  • That function compares the typed name and each heard word as exact text (after case and punctuation clean-up).
  • The speech-to-text adapter is told the language is Hindi, so the audio comes back in Devanagari ("कृष्ण"), but

you type the name in Roman letters ("Krishan"). Those never match. Different Roman spellings ("Krishan", "Krishn", "Kishan") do not match each other either.

  • A word under the confidence limit (stt_confidence_threshold, default 0.6) counts as "not found", with no clue

why. The result is SLOT_NOT_FOUND and you have to mark the time by hand.

What we will build (plain language)

  1. Sound-alike matching across scripts. Both the typed name and every heard word are turned into a simple

"sound skeleton" (consonants and long vowels, with the usual Hindi/English spelling differences smoothed out: v/w, sh/s, ph/f, double letters, matras, anusvara, nukta). Words are compared by how close the skeletons are, from 0 to 1. No new library: plain Python rules we can test.

  1. Closest 3 candidates. If no word is close enough, the analysis result lists the 3 closest heard words with

their time, their closeness and the speech-to-text confidence, including words below the confidence limit. The dashboard shows them as buttons: "Use this word". Picking one only sets the slot; you still confirm it, as today.

  1. Whisper hint. The expected name is passed to Whisper as a hint (its hotwords / initial prompt option, in

Devanagari and as typed), so it is more likely to write the name down.

  1. Model size test. A script compares Whisper model sizes on the demo templates (found or not, time, memory)

and prints a table. You pick the default. No change of default without your decision.

Rules that do not change

  • A found slot is never confirmed automatically (slot_confirmed stays false). You always confirm. The content

lock and consent gate are untouched.

  • Local AI mode stays offline at run time. Real voter data is not used in tests: only made-up words.

Acceptance criteria

  1. AC1 The typed name "Krishan" matches a heard "कृष्ण", "किशन" and "krishan" (and a labelled list of at least 20

made-up name pairs, in both scripts, matches at 90 % or better). Unrelated words do not match.

  1. AC2 A match needs closeness at or above a setting (name_match_threshold, default 0.8, range 0 to 1) and

confidence at or above stt_confidence_threshold. Both are settings, no magic numbers.

  1. AC3 When nothing passes, the result lists up to 3 closest words, best first, each with time, closeness and

confidence. Words below the confidence limit may appear there but are never chosen automatically.

  1. AC4 An empty transcript, one word, or silence gives a clear "not found" with an empty list. No crash.
  2. AC5 The dashboard shows the candidates; picking one sets the slot, and the slot still needs your confirmation.
  3. AC6 The expected name is passed to the speech-to-text adapter as an optional hint; with no hint, behaviour is the

same as today. Fake and Modal adapters accept the new argument.

  1. AC7 The model-size script runs offline on the demo templates and prints one table. It changes no setting.
  2. AC8 Existing behaviour is kept: an exact match still works, and a typed name with a single character or only

punctuation is refused clearly, not matched loosely.

Decisions for you (recommended answer first)

  1. Keep candidates only in the response, not in the database (Recommended). No migration. After a page reload

you press "Analyse again" (a few seconds on CPU). The alternative stores them in a new slot_candidates column, which is migration 0004 and needs your separate approval.

  1. Plain rules for the sound skeleton (Recommended). Alternatives: a transliteration library (new dependency)

or the local Qwen model (heavy, not in CI).

  1. Closeness default 0.8, tuned on the made-up list in AC1. Lower finds more but guesses more.
  2. Model-size test downloads Whisper weights for the sizes we do not have yet (MIT licence, a few GB). The

script uses only a folder you name and never downloads by itself. Say yes to each size, or run it with the sizes already on the Mac.

Test case tree (outline; the tester expands it in docs/test-tree/better-name-detection.md)

  • Skeleton and closeness: positive (Krishan / कृष्ण / किशन / Krishn), negative (Krishan vs Ramesh),

edge (empty, one letter, only punctuation, mixed script, zero-width joiner, uppercase, long name, repeated letters, numbers).

  • Accept rule: positive (close and confident), negative (close but low confidence is a candidate, not a match;

confident but far is nothing), edge (exactly at both thresholds, ties on closeness, same word twice).

  • Candidates: positive (top 3 best first), negative (fewer than 3 words, none), edge (identical scores,

duplicate words, a hundred words).

  • Service and API: analysis returns match, candidates or not found; slot stays unconfirmed; picking a candidate

sets the slot; unauthenticated and wrong template are refused.

  • Whisper hint: passed when given, absent when not; fake, local and Modal adapters accept it.
  • Dashboard: candidate buttons show, picking sets the slot, empty list shows the old message, errors show.
  • Script: prints a table, runs without network, refuses a missing folder.
