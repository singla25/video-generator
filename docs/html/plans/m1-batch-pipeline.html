Plan — M1: Batch pipeline on fake AI models

Status: Approved (Admin, 2026-10-18) · Date: 2026-10-18 · Requirements: docs/requirements/REQ-001-requirement-tree.md ADRs: 001 (Python 3.11 + uv) · 002 (Dramatiq) · 003 (Postgres) · 004 (FFmpeg) · 005 (PII encryption) · 006 (auth) · 007 (sheet parsing) · 008 (ports + fakes)

Goal

Build and fully test the complete backend flow of REQ-001 (upload → validate → template + consent → preview → approve → queued rendering → output folder + manifest → status/analytics → downloads, retries, deletion), running end-to-end on a Mac CPU. Every AI step sits behind its port with a deterministic fake adapter, so M2 only has to plug in the real models.

Acceptance criteria (each has ≥1 automated test)

  1. AC1 Video upload — MP4/MOV with H.264/H.265 within the size/duration limits (settings) is accepted. Any other container or codec, a renamed non-video, a corrupt file, or a file over the limits is rejected with a coded, plain-language error, and nothing is stored. The type is checked with ffprobe, not the file extension.
  2. AC2 Sheet upload — .xlsx and .csv are accepted. Headers match case-insensitively with whitespace trimmed (VID = vid). The user maps Name, ID and an optional Spoken name. A missing mapped column gives a clear error and creates no batch.
  3. AC3 Row validation — empty name, empty ID, duplicate ID (first row kept; the error names the earlier row), name > 40 chars, and characters outside Latin/Devanagari/space/./-/' each give their R8 code. Invalid rows are SKIPPED and never rendered. All limits come from settings.
  4. AC4 Validation speed — a 1,000-row sheet validates in < 3 s. A 100,000-row sheet is processed in a stream (memory stays flat, tested via a bound on peak memory).
  5. AC5 Consent gate (C1) — a template is usable only after a consent file (PDF/PNG/JPG, type-checked) is uploaded and confirmation is ticked. Otherwise rows fail CONSENT_MISSING. Consent is stored with the template profile and logged in the audit log.
  6. AC6 Template profile (R2.1/2.3/2.4) — analysis runs the SpeechToText port (fake in M1) and locates the target word with timestamps. Low confidence or no match means the user must mark the slot manually. A manual slot outside the video duration is rejected. The profile is stored and reused by later batches with no re-analysis.
  7. AC7 Preview gate — a preview of row 1 is rendered through the queue. A batch cannot start until that preview is approved. Approval and start are audited.
  8. AC8 Output format (R6.1, Q7) — every output keeps the template's resolution, fps, video codec family and audio format. Duration = template + name delta (D16) ±50 ms.
  9. AC9 Audio splice (R3.4/R3.5, D16) — only the slot audio changes. Audio outside the slot (minus the crossfade zones) matches the template. Crossfades are 20–50 ms, and loudness of the spliced slot is within ±1 LU. Timing: time-stretch ≤ ±15 %, then pause absorption, then extension ≤ 1.5 s. Beyond that, the row fails NAME_TOO_LONG_TO_SPEAK. Shorter names pad the pause.
  10. AC10 AI label + metadata (C2/C3, Q8) — every frame carries the "AI-Generated / एआई-जनित" label at the top, covering ≥ 10 % of the frame area. MP4 metadata contains the creator entity (setting), generation date and batch ID.
  11. AC11 Output folder & files (R6.2–R6.4, Q9) — the default folder is YYYY-MM-DD-<valid rows>, or a custom name. An existing folder gets a -2/-3 suffix; nothing is ever overwritten. Path traversal and illegal characters are rejected. Files are named <ID>.mp4 with unsafe chars → _. manifest.csv has one line per input row, and its statuses add up to the total.
  12. AC12 Queue reliability — rows are independent Dramatiq jobs. A crash, timeout or storage error is retried exactly once automatically. Quality failures are not retried. A re-delivered job produces no duplicate file. Disk full → STORAGE_ERROR with no partial file. Temp files are removed on success and on failure.
  13. AC13 Batch control — pause stops new rows from starting and resume continues. Cancel marks unstarted rows CANCELLED. Retry-failed re-queues only failed rows. Submitting the same batch twice is idempotent.
  14. AC14 Status & analytics API (R7) — overview counts (Total, Completed, Processing, Queued, Failed, Skipped, Cancelled) always add up to the total. Also: progress + ETA, failure breakdown by code, rows list with status filter, search and paging, batch history with success rate, and time-series stats (videos/day, average render time).
  15. AC15 Downloads — a single video, ZIP of all outputs (streamed), and a failures CSV.
  16. AC16 Auth (ADR-006) — every endpoint except login/health requires the session cookie. State-changing calls require the CSRF token. Wrong password returns 401 and repeated failures are rate-limited.
  17. AC17 Privacy (C5) — names and IDs are encrypted at rest (no plaintext in DB rows). No fixture name or ID appears in captured logs. Deleting a batch removes its rows, files and personal data. The retention job deletes data older than N days (default 30). Audit entries survive deletion without personal data.
  18. AC18 Content lock (C6) — the pipeline can only change the slot range. Attempting to set a slot outside the confirmed profile is rejected.
  19. AC19 Quality — uv run pytest passes; ruff check, ruff format --check and mypy --strict backend are clean. Coverage is ≥ 85 % overall and 100 % on domain/ and on the render_row pipeline service.

Addendum A — clarifications from T1 review (Admin approved 2026-10-18)

These close the gaps the tester found while drafting the test tree. They are binding for all M1 tests and code.

#TopicRule
A1Name length (AC3)40 = grapheme clusters (user-perceived characters), not code points. ZWJ (U+200D) and ZWNJ (U+200C) are allowed inside Devanagari.
A2Duplicate ID (AC3, AC11)Compare IDs after trim → case-fold → file-name sanitising (R6.3). RJ/12/097 and rj_12_097 are duplicates, because they would produce the same file. The first row is kept.
A3Existing codesEmpty name / empty ID / duplicate → INVALID_ROW_EMPTY_NAME, INVALID_ROW_EMPTY_ID, DUPLICATE_ID (already in R8).
A4New codesUpload errors: UNSUPPORTED_VIDEO, CORRUPT_VIDEO, UNSUPPORTED_SHEET, COLUMN_NOT_FOUND. Template errors: SLOT_NOT_FOUND, STT_FAILED. Row errors: CONTENT_LOCK_VIOLATION, INTERNAL_ERROR (catch-all; never retried automatically unless it is a crash).
A5Preview approval (AC7)Changing the slot, template or column mapping after a preview invalidates the approval; a new preview + approval is required.
A6Cancel (AC13)Rows already PROCESSING finish and are delivered. Only QUEUED rows become CANCELLED.
A7Manifest (AC11)manifest.csv contains row number, name, ID, status, file name, failure code + message, render time. It is personal data: covered by retention and batch deletion.
A8Retention (AC17)The retention job skips batches that are not finished (queued / running / paused).
A9ThresholdsAC4: peak memory for 100k-row validation ≤ 200 MB above baseline. AC9: outside the slot (excluding crossfade zones) the audio difference vs. template ≤ −40 dB RMS. AC10: label is a full-width band, height ≥ 10 % of frame height, at the top, in every sampled frame. AC16: 5 failed logins within 15 min → locked (HTTP 429) for 15 min.
A10WorktreesThe guard blocks writes under .claude/worktrees/. Until the Admin changes that, tasks run sequentially in the main project folder, one branch at a time. T1 runs on feat/tester/m1-tree.

Addendum D — domain contract choices from T3 (CEO accepted 2026-10-18)

#Rule
D-1A slot shorter than 2 × crossfade → SlotTooShortError. A zero-length manual slot is rejected.
D-2plan_timing only compresses longer audio (≤ 15 %); it never slows speech down. Shorter audio pads the pause (D16).
D-3Folder names are NFC-normalised; Windows reserved names (CON, NUL, …) are rejected as INVALID_FOLDER_NAME.
D-4Output file names: spaces and other unsafe characters → _ (R6.3); the name is capped at 255 bytes.
D-5Accented Latin letters (é, ñ…) are invalid name characters (D9: ASCII A–Z/a–z only). Corrected in T3 round 2.
D-7T4 gap-fillers (CEO accepted): ZWJ/ZWNJ only between Devanagari characters · Devanagari digits and dandas are not name characters · only valid rows register their ID for duplicate detection (an invalid earlier row never blocks a later valid one) · header ambiguity → UNSUPPORTED_SHEET, duplicate mapping → COLUMN_NOT_FOUND · too-short slot → SLOT_NOT_FOUND · state-machine errors are plain exceptions (programming errors, not user-facing) · a quality failure without a specific code → OUTPUT_CHECK_FAILED.
D-8T5 infrastructure contracts (CEO accepted): separate VideoProbe port (FfprobeVideoProbe, VideoLimits, VideoInfo) instead of VideoEncoder.probe · unreadable media → CORRUPT_VIDEO; wrong container/codec, no audio, too short/long/big → UNSUPPORTED_VIDEO; ffprobe timeout or missing binary → INTERNAL_ERROR · storage key collision → name-2.ext… (never overwrite); OSError → STORAGE_ERROR; delete is idempotent · cipher: 32-byte AES keys, index key ≥ 32 bytes, empty string allowed, blind index = hex HMAC-SHA256 over id_key(value), repr never shows keys · reader: missing/empty/non-UTF-8/undetectable-delimiter → UNSUPPORTED_SHEET. Max-rows check moves to the batch service (T11). Odd-dimension video not tested (ffmpeg cannot produce it).
D-9T6 accepted: ports/models.py (SheetRow, VideoInfo, VideoLimits) · first visible xlsx sheet · rows padded to header width · mp4/mov told apart by major_brand · storage publishes via os.link (cannot overwrite; needs a hard-link-capable filesystem; the S3 adapter in M2 uses conditional put instead).
D-10AI label style (Admin 2026-10-18): opaque solid band across the full width at the top, height ≥ 10 % of frame height (e.g. 130 px on 1080×1300), light text on a dark band, bilingual "AI-Generated / एआई-जनित", on every frame. It covers the top of the template; the resolution never changes (R6.1).
D-11Video extension in M1 (Admin 2026-10-18): when the timing plan extends the video (D16), the video frames under the slot are retimed (played slower) to cover slot + extension; no frozen frame. M2 lip sync replaces these frames.
D-12Devanagari text shaping (Admin 2026-10-19): the label renderer requires Pillow's complex-text layout (raqm). New system dependency libraqm (dev: brew install libraqm + symlink the dylibs into /usr/local/lib, see ADR-001 "Devanagari text shaping"; GPU worker image in M2: the distro's libraqm package). A test asserts shaping is active, so the label never ships unshaped. Speech stretch uses atempo in M1 (this FFmpeg build has no rubberband); revisit in M2 with the real voice.
D-13The target word is per template (CEO, 2026-10-19, from REQ-001 §1): each template stores original_name, the spoken voter name to replace ("Krishan" in the sample). It is given at template creation and used by slot detection. It is not a global setting, and never "ji".
D-14Migration 0001 rules (Admin 2026-10-19): (1) upgrade only creates tables and indexes: no drop, alter or data changes; (2) downgrade drops exactly those tables in reverse order; (3) PII columns (name, spoken_name, voter_id) are encrypted bytes, plus a blind-index column; no plaintext PII columns; (4) an automated test (Admin-approved) runs upgrade → downgrade → upgrade on a separate throwaway DB vidgen_migration_test (name guard: must end in _test) and asserts that the migrated schema matches the models (autogenerate diff empty); it never touches the vidgen dev DB; (5) migrations/env.py needs only the DB URL (no secrets/full Settings); (6) the Admin runs it on the dev DB after CEO review and explicit approval.
D-15Login protection (Admin 2026-10-19, revised the same day), refines A9: (1) Per client: 5 failures from one client within 15 min lock that client for 15 min (HTTP 429 + Retry-After; the correct password is refused too). (2) Global cap → throttle, not lock: after 50 failures from all clients within 15 min, all login attempts are rate-limited for 15 min to 1 attempt per 5 s globally (429 + short Retry-After). A correct password inside the allowed rate still succeeds, so an attacker can slow the admin's login but never block it. (3) Existing sessions are never affected by either rule; only /auth/login is limited. (4) Alert: crossing the global cap writes one SECURITY_LOGIN_THROTTLED audit event per window (no passwords, no PII), shown on the dashboard in M3. (5) Client address: the direct peer address, unless the peer is in the setting trusted_proxies (list of IPs/CIDRs, empty by default). Only then is X-Forwarded-For used, taking the right-most address that is not itself a trusted proxy. Thresholds, throttle rate and window are settings.
D-16T9 contracts accepted: API codes UNAUTHENTICATED, INVALID_CREDENTIALS, CSRF_FAILED, RATE_LIMITED, NOT_FOUND, VALIDATION_ERROR · oversize upload 413, storage failure 507, STT failure 502 · template usable = consent confirmed + slot confirmed; editing the slot un-confirms it · no transliteration in M1, so a Latin original_name vs a Devanagari transcript → manual slot (M2 adds transliteration).
D-17T10 review fixes (CEO, 2026-10-19): (1) login-protection state (per-client failures, global throttle window, alert window) is persisted in Postgres (a table in 0001), not in-process (stateless API rule), and shared across API instances and restarts; (2) a partial unique index on batch_rows(batch_id, voter_id_index) WHERE status <> 'SKIPPED', so the DB itself prevents two renderable rows with the same ID; (3) an index on batches(finished_at) for the retention job. Migration 0001 is amended before anyone runs it.
D-18T10 round-2 choices (CEO accepted; Admin confirmed 2026-10-19): login_attempts(campaign_id, client_key, window_started_at, failure_count, locked_until, last_allowed_at), PK (campaign_id, client_key), global row key *, row-locked per attempt, stale rows pruned on write · failure counting uses a fixed window from the first failure (not sliding). Same long-run rate; at most a short burst across a window boundary. Acceptable for M1; revisit if needed · the repository raises the raw IntegrityError for a live duplicate. The batch service (T12) must map it to DUPLICATE_ID so the API never returns a 500 for it (T11 tests will check this).
