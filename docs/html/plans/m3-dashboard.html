Plan — M3: Operator dashboard (F1–F6)

Status: Draft — needs Admin approval · Date: 2026-10-19 Inputs: REQ-001 §7 (R7), §10 · docs/design/reference/DESIGN-NOTES.md + trustvest-dashboard.png · ADR-006 (auth), ADR-009 (stack) · M1 API (T10–T14) Schedule: starts after M1 merge gate 3 (backend + tests verified, as the Admin asked). Can run in parallel with M2 backend work (worktrees, if the guard allows; otherwise interleaved).

Goal

A TrustVest-style dashboard over the M1 API with these parts:

  • an overview with live KPIs and charts
  • a 4-step New batch wizard
  • batch detail with the rows table
  • templates with consent status
  • history
  • a security (audit) view

It has a clean design, correct Hindi text and accessible motion, and every screen handles loading, empty and error states.

Acceptance criteria

  1. UI-AC1 Design fidelity: colours, card style (1 px border, 12–14 px radius, near-zero shadow, 20–24 px padding), typography (Plus Jakarta Sans + Noto Sans Devanagari), chips, hatched stepped chart and spacing follow DESIGN-NOTES §1. Tokens are defined once in the Tailwind config. A visual review against the reference is signed off by the Admin.
  2. UI-AC2 Layout:
  3. The sidebar has MENU (Overview, Batches → Running/Completed/Failed, Templates, History, Security) and GENERAL (Settings, Help).
  4. The header shows the page title, + New batch and the avatar.
  5. It is responsive down to tablet width (768 px).
  6. UI-AC3 Overview (R7.1, R7.2, R7.6):
  7. Six KPI cards (Total · Completed · Processing · Queued · Failed · Skipped) with status chips, plus a dashed New batch card.
  8. A "Videos generated" hatched stepped chart (day/week) with the big total and a "+X % vs last" pill.
  9. A Current batch panel: progress ring, ETA, counts, Pause/Resume/Retry failed, and the lime main action.
  10. Live updates poll every 2 s, and the counts always add up.
  11. UI-AC4 Rows table (R7.4):
  12. Columns: Name (Devanagari OK), ID, status chip (Completed green · Processing blue · Queued grey · Failed red · Skipped amber), failure reason in plain words, render time, and actions (preview, download, retry).
  13. Search by name or ID, filter by status, paged. It stays smooth with 1,000 rows (virtualised or paged).
  14. UI-AC5 New batch wizard (4 steps):
  15. Steps: upload (drag-and-drop video + sheet with preview) → map columns & validate (invalid rows highlighted with reasons) → mark slot & preview (video player, timeline with the detected slot, editable range, Generate preview, approval required) → output folder & start (default YYYY-MM-DD-N pre-filled, confirm screen).
  16. It respects the preview gate (A5), the consent gate and the API's error codes.
  17. UI-AC6 Batch detail (R7.3, R7.7):
  18. Header stats, progress bar + ETA, a failure-reason chart (clicking a reason filters the rows), and an inline video preview.
  19. Actions: Download ZIP, Export failures CSV, Pause/Resume/Cancel and Retry failed. Each confirms first where it can't be undone.
  20. UI-AC7 Templates: cards show a thumbnail, the consent badge (✓ / missing), a slot summary, the original name and a usable state. Consent upload + confirmation flow.
  21. UI-AC8 History & Security (R7.5, C4, D-15):
  22. History: past batches with date, template, totals and success rate.
  23. Security: the audit log with filters.
  24. A security alert banner appears when a SECURITY_LOGIN_THROTTLED event exists.
  25. UI-AC9 Auth:
  26. A login screen. The session cookie is never read by JS; the CSRF token is sent as X-CSRF-Token on every state-changing call.
  27. A 401 leads to login, and 429 shows "Too many attempts, try again in N s".
  28. UI-AC10 States & motion:
  29. Every screen has loading (skeletons), empty and error states (the API being down shows an error state, not stale numbers).
  30. Count-up and grow-in animations are disabled under prefers-reduced-motion.
  31. UI-AC11 Hindi: Devanagari names render correctly (shaping, no tofu) in the table, wizard and previews.
  32. UI-AC12 Privacy:
  33. No external network requests: fonts self-hosted, no CDNs, no analytics.
  34. No voter data is stored in localStorage or sessionStorage.
  35. The TrustVest name, logo and designer photo don't appear anywhere in frontend/.
  36. UI-AC13 Quality:
  37. TypeScript strict, ESLint + Prettier clean.
  38. Component tests ≥ 85 % line coverage on frontend/src.
  39. Playwright end-to-end on the main flows, plus axe accessibility checks with no serious violations.

Test tree outline (tester expands into docs/test-tree/m3-dashboard.md)

Dashboard
├── Auth: login ok / wrong / 429 countdown / 401 → login / CSRF header on POST
├── Overview: KPIs add up · polling updates · API down → error state · empty (no batches) · reduced motion
├── Rows table: chips per status · Devanagari names · search · filter · 1,000 rows smooth · retry/download actions
├── Wizard: upload validation messages · mapping + invalid rows · slot edit + preview gate · folder default/custom/invalid
├── Batch detail: failure chart click-through · ZIP / CSV · pause/resume/cancel confirmations
├── Templates: consent missing → not usable · consent upload + confirm
├── History / Security: success rate · audit filters · throttle alert banner
└── Cross-cutting: tablet width · keyboard navigation · axe · no external requests · no PII in browser storage
