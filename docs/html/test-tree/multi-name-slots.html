Test tree: several name slots, dashboard (DD-40, task FE-RED)

Plan: docs/plans/multi-name-slots.md (AC3, AC4, AC9, AC10). The template JSON gets extra_slots and slots; PUT /api/templates/<id>/slot takes extra_slots (always sent). The slot editor (SlotEditor, used by the wizard step 3 and the Templates card) adds up to 4 extra pairs and runs client-side checks. The template card lists all slots.

Files:

  • tests/frontend/unit/multi-slot-editor.test.tsx (editor, wizard step 3, PUT body, confirm again)
  • tests/frontend/unit/multi-slot-card.test.tsx (card text, card editor prefill)
  • tests/frontend/mocks/data.ts and handlers.ts (fixtures and default PUT handler that records bodies)

Decisions from the Admin (through the CEO), now encoded in the tests:

  1. The primary slot keeps its existing messages: end past the video -> "The slot must be inside the video (20 s)."

and end <= start -> "End must be after start." (P19, P20). The new messages are for extra slots only: "Slot N ends after the video." and "Each slot must end after it starts.".

  1. After a removal the extra slots are renumbered, so the labels follow the position (P21, P22).
  2. extra_slots in the PUT body are sent sorted ascending by start, whatever the typing order (P23, P24).

Overlap ("Slots must not overlap or touch.") and "Fill in every slot or remove it." check all slots.
