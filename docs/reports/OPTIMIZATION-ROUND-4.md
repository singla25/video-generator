## Checked and sound (no finding)

- **Dependencies:** `npm audit --omit=dev --audit-level=high`: 0 vulnerabilities. `pip-audit`: 1 (finding 2).
- **Authentication:** every router carries a session or CSRF dependency. Open paths are only `/health`, `/system/status` and `/auth/*` (`api/schema_gate.py:20-21`). Note `/system/status` is open in the gate but its router requires a session (`routes_system.py:18`).
- **Cookies and CSRF:** the session cookie is `HttpOnly`, `SameSite=Strict`, `Secure` by default (`settings.py:97`); the CSRF token is compared in constant time (`api/security.py`); the cookie is signed with `itsdangerous`, versioned and expiring.
- **Login limiter:** per-client lockout (5 failures, 15 minutes) and a global throttle, stored in Postgres under a lock. The client address takes the right-most untrusted `X-Forwarded-For` entry (`api/client_address.py`), so a spoofed header does not split counts.
- **Uploads:** streamed with a hard size limit and temp-file cleanup (`api/uploads.py`); only a sanitized extension is kept from the client file name; consent files are type-sniffed (`services/templates.py:134`).
- **Path traversal:** storage keys reject empty, absolute, `..`, NUL and anything resolving outside the root (`infrastructure/storage/local.py:23,89-95`).
- **Personal data in logs:** every `logger.*` call and `extra=` I found in `backend/vidgen` logs only error types, ids and counts. No names or voter ids.
- **API surface:** interactive docs are off (`docs_url=None`, `redoc_url=None`), and there is no CORS middleware (same origin only).
- **SQL:** SQLAlchemy with bound parameters; I found no string-built SQL (grep, not an exhaustive proof).
